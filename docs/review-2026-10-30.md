# Compute integration review (2026-10-30)

Scope: `feat/codelab` against the Drive-enabled main branch (`cc138aba5`),
including OAuth, job scheduling/recovery, workspace transfers, billing,
resource groups, routing and product navigation. Existing API features were
checked for regressions; this is not a claim of a security audit of every
upstream file.

## Corrections

- Reject JSON execution notifications without a terminal result, null results,
  and unexpected response IDs. These previously allowed a nil dereference or
  a false successful result. SSE progress notifications remain supported.
- Publish output paths and save execution logs before workspace artifacts.
  Failed setup may not create an archive; users can now fetch the logs anyway.
  A writeback error no longer replaces the original execution error.
- Check database iteration errors before selecting an account or deciding
  hardware is unavailable. A late selection failure cannot overwrite a
  concurrently cancelled queued job. Canonicalize job UUIDs before allocation.
- Exclude FIFOs and other nonregular files from CLI packaging. Cancel invalid
  upload tickets without replacing the original transfer error with a cleanup
  failure.
- Present API, storage and compute through a shared summary component with
  distinct icons, metric scopes, independent errors and detail links. Remove
  duplicate administrator API metric markup. Preserve user provider quotas.
- Reuse the storage icon and show unknown storage values as unknown, not zero
  or unlimited. Keep Google account/CU details out of ordinary user summaries.

## Verified invariants and limits

- Replacing a Drive file publishes a new node. A task pinned to the old node
  cannot silently read replacement contents. Deleted/replaced inputs fail.
- Runtime transfer credentials are job-scoped and require an active job;
  user-facing status and job queries remain scoped to the authenticated user.
- Billing reserves atomically, snapshots each task's price, refunds unused
  reservation and settles idempotently after runtime release. This review
  does not change existing prices, balances or historical charges.
- GPU availability is provider eligibility, not a capacity guarantee.
  Google CU is a timestamped upstream snapshot, not platform credit.
- Failed output writeback may leave partial files; the output path and error
  remain visible. If Drive itself is unavailable, captured logs remain in the
  job record. Process crashes/timeouts cannot guarantee capture of all logs.
- Input uploads and artifact uploads are direct to Google. Runtime input and
  result downloads still traverse the service. Workspace/file limits remain
  in force; this is not an unbounded cluster scheduler.

## Validation

CLI failure-path tests cover missing artifacts, invalid upload hosts,
cleanup failure and FIFO exclusion. Go tests cover execution protocol parsing,
output ordering and failure retention in addition to the existing authorization,
billing, workspace and storage tests. Frontend tests cover independent failures,
all three product panels, refresh, hidden upstream data and preserved quotas.
The release also requires typecheck, production build, live HTTPS/auth/storage/
compute checks, and Edge visual verification before deployment is accepted.
